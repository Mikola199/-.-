# 10. Руководство администратора и разработчика (EQUHUB Manual)

Данный документ представляет собой техническое руководство для инженеров, разработчиков и администраторов, занимающихся развитием, развертыванием и эксплуатацией Единой цифровой платформы **EQUHUB**.

---

## 10.1 Руководство разработчика (Developer Guide)

### 10.1.1 Структура репозитория (Repository Structure)

В соответствии с разделом 14 SRS, проект спроектирован как монорепозиторий, содержащий веб-фронтенд, мобильное приложение и набор независимых микросервисов:

```text
/
├── app/                  # Web Frontend: Next.js 14 (App Router)
│   ├── api/              # API-роуты фронтенда (прокси до микросервисов)
│   └── globals.css       # Глобальные стили (переменные дизайн-системы)
├── components/           # UI-компоненты React (Header, ThemeProvider, ListingCard)
├── lib/                  # Утилиты, ИИ-модели, типы и мок-данные (mockData.ts, ai.ts)
├── docs/                 # Техническая документация (ERD, OpenAPI, UML, Спецификации)
├── public/               # Статические ассисты (изображения, скриншоты E2E)
├── tests/                # Сценарии тестирования (Pytest, Playwright UI Verification)
├── package.json          # Конфигурация зависимостей Node.js Workspace
├── tsconfig.json         # Строгая типизация TypeScript
└── dating_chatbot.py     # Вспомогательный модуль чат-бота для знакомств
```

### 10.1.2 Инструкции по локальному запуску

#### Шаг 1: Клонирование и подготовка окружения
Убедитесь, что на вашей машине установлены **Node.js (v18+)** и **Python (3.11+)**.

```bash
# Клонирование репозитория
git clone https://github.com/Mikola199/equhub-platform.git
cd equhub-platform

# Установка зависимостей Node.js
npm install
```

#### Шаг 2: Запуск веб-фронтенда в режиме разработки
Next.js запустится на порту `3000`.
```bash
npm run dev
```
После старта откройте в браузере [http://localhost:3000](http://localhost:3000). Перед вами появится премиальный интерактивный дашборд EQUHUB с симулятором супер-аппа.

#### Шаг 3: Настройка и запуск тестов Python
```bash
# Инициализация виртуального окружения (опционально)
python -m venv venv
source venv/bin/activate  # Для Linux/macOS
# venv\Scripts\activate   # Для Windows

# Установка зависимостей
pip install pytest playwright

# Запуск модульных тестов
pytest -v
```

### 10.1.3 Проведение миграций базы данных (PostgreSQL)

Слой данных в микросервисах управляется через ORM: **Prisma** (для NestJS) и **Alembic** (для Python/FastAPI).

#### Применение миграций в NestJS (User, Market Services):
```bash
# Генерация миграции по схеме Prisma
npx prisma migrate dev --name init_equhub_schema

# Применение миграций на продакшне
npx prisma migrate deploy
```

#### Применение миграций в FastAPI (Auth Service):
```bash
# Создание ревизии Alembic
alembic revision --autogenerate -m "add_two_factor_auth_fields"

# Применение миграции
alembic upgrade head
```

## 10.2 Руководство администратора (Administrator Guide)

Администраторы управляют платформой через **Admin Panel** (Панель администратора EQUHUB), доступную по адресу `https://admin.equhub.ru` для пользователей с ролью `super_admin` или `moderator`.

### 10.2.1 Основные задачи администрирования

1.  **Модерация контента (Жалобы - Reports):**
    *   При поступлении жалобы от пользователя в панели отображается целевой объект (пост, объявление, комментарий), причина жалобы и статус.
    *   Модератор имеет право в один клик перевести объявление в статус `moderated` (скрыть с маркетплейса) или деактивировать пост в СУБД.
2.  **Разрешение диспутов в безопасных сделках (Escrow Arbitration):**
    *   Если покупатель или продавец открыл Спор (статус сделки: `спор`), средства блокируются на транзитном счете Payment Service.
    *   Арбитр просматривает историю чата сделки (через зашифрованную выгрузку, если разрешено настройками приватности).
    *   По итогам разбора арбитр нажимает кнопку **"Выплатить продавцу"** (вызов API `/escrow/release`) или **"Вернуть покупателю"** (вызов API `/escrow/refund`). Средства автоматически распределяются по кошелькам.
3.  **Управление учетными записями и блокировками:**
    *   При обнаружении спам-активности или скам-объявлений (автоматически помеченных ИИ-сервисом с низким показателем `ai_score` < 50) администратор может временно или навсегда заблокировать пользователя (`is_active = FALSE`).
4.  **Мониторинг логов аудита:**
    *   Администратор безопасности обязан регулярно просматривать логи в `AuditLogs` для выявления аномалий: множественные неудачные попытки входа с разных IP-адресов, резкие изменения баланса кошельков, несанкционированные попытки доступа к эндпоинтам.
