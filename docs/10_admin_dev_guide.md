# EQUHUB — Единая цифровая платформа

## Документ 10: Руководство администратора и разработчика (Onboarding & Operations Guide)

### 1. Быстрый старт для разработчиков (Onboarding)

Добро пожаловать в команду разработки EQUHUB! Платформа спроектирована как единая экосистема Next.js веб-фронтенда и набора бэкенд-микросервисов.

#### 1.1. Подготовка окружения
Убедитесь, что на вашей локальной машине установлены:
*   **Node.js** v20.x+ и менеджер пакетов `npm`
*   **Python** v3.11+
*   **Docker** и **Docker Compose**

#### 1.2. Установка зависимостей проекта
В корневой директории проекта выполните команду для установки Node.js зависимостей фронтенда:
```bash
npm install
```

Для установки Python-зависимостей юнит-тестов и ассистента:
```bash
pip install -r requirements.txt  # или вручную pip install pytest playwright python-jose passlib bcrypt
```

#### 1.3. Локальный запуск баз данных и инфраструктуры
Запустите Docker Compose в фоновом режиме:
```bash
docker compose up -d
```
Эта команда поднимет PostgreSQL, Redis, Elasticsearch и MinIO.

#### 1.4. Запуск Next.js фронтенда в режиме разработки
```bash
npm run dev
```
Фронтенд будет доступен по адресу `http://localhost:3000`. Интерактивный симулятор работает локально и симулирует передачу JSON-сигналов между всеми 14 микросервисными узлами.

### 2. Поддержка гигиены репозитория и коммитов (Commit Hygiene)

Перед отправкой изменений в удаленный репозиторий (Pull Request) строго соблюдайте следующие правила коммит-гигиены:
1.  **Удаление кэша сборки TypeScript:** Файлы типа `tsconfig.tsbuildinfo` генерируются локально при сборках и вызывают конфликты слияния. Убедитесь, что они отсутствуют в коммите.
2.  **Очистка кэша Python:** Проверяйте отсутствие папок `__pycache__/` и файлов `.pyc` в вашем `git status`. Всегда добавляйте их в локальный `.gitignore`.
3.  **Исключение зависимостей:** Каталог `node_modules/` никогда не должен добавляться в коммиты.
4.  **Сброс лишних файлов перед коммитом:**
    ```bash
    git reset HEAD tsconfig.tsbuildinfo
    rm -f tsconfig.tsbuildinfo
    ```

### 3. Руководство администратора (Панель Управления & Операции)

#### 3.1. Управление базой данных (Миграции)
Для изменения схемы базы данных и наката миграций в PostgreSQL используется инструмент **Prisma** или **TypeORM/Alembic** (в зависимости от сервиса).
Пример наката миграций:
```bash
npx prisma migrate deploy
```

#### 3.2. Модерация контента через AI
Встроенный AI-модератор автоматически помечает и блокирует объявления, содержащие стоп-слова:
*   *Обман, схемы легкого заработка, пирамиды, крипта.*
*   Такие объявления переводятся в статус `moderated` и требуют ручного подтверждения администратором на панели управления.

#### 3.3. Мониторинг логов
Живая трассировка логов событий API Gateway и шины RabbitMQ доступна в симуляторе в реальном времени. В промышленной среде рекомендуется развернуть стек **ELK (Elasticsearch, Logstash, Kibana)** или **Prometheus & Grafana** для анализа метрик CPU, памяти и задержек сетевых пакетов.
