# Руководство администратора и разработчика EQUHUB (Developer Guide)

Настоящий документ является полным техническим руководством для инженеров, разработчиков и администраторов Единой цифровой платформы **EQUHUB** в соответствии с Разделами 14 и 15 (Пункт 10) Требований к программному обеспечению (SRS).

---

## 1. Структура репозитория и архитектура кода

Хотя оригинальный SRS предлагает монорепозиторную структуру с каталогами `/apps` и `/services`, текущая стабильная версия репозитория реализована в виде оптимизированного единого Next.js-проекта с автономной интеграцией микросервисов, что обеспечивает удобство локальной разработки и деплоя:

```text
/
├── app/                  # Frontend Next.js 14 (App Router)
│   ├── api/              # Локальные API-роуты / мок-контроллеры
│   ├── globals.css       # Глобальные стили, CSS-переменные дизайн-системы
│   ├── layout.tsx        # Корневая разметка страниц
│   └── page.tsx          # Главная интерактивная концепт-страница EQUHUB
├── components/           # Переиспользуемые React / TypeScript компоненты UI
│   ├── Header.tsx        # Шапка платформы
│   ├── ListingCard.tsx   # Карточка товара маркетплейса
│   └── ThemeProvider.tsx # Провайдер тем оформления
├── lib/                  # Утилиты, типы и бизнес-логика
│   ├── ai.ts             # Логика AI-ассистента и автомодерации
│   ├── auth.ts           # Утилиты авторизации и работы с JWT
│   ├── mockData.ts       # Наборы реалистичных демонстрационных данных (Вакансии, Сделки)
│   └── types.ts          # Строгая TypeScript типизация сущностей
├── public/               # Статические файлы, медиа-ресурсы, HTML-страницы
│   └── sound_gen.html    # Standalone-страница звукового генератора
├── tests/                # Набор автоматизированных тестов
│   ├── conftest.py       # Конфигурация путей импорта для pytest
│   ├── test_dating_chatbot.py # Модульные тесты Python утилит
│   └── verify_sound_gen.py    # Playwright E2E скрипт верификации интерфейса
├── package.json          # Зависимости Next.js, React, TypeScript
└── tsconfig.json         # Параметры компилятора TypeScript
```

## 2. Руководство для разработчика (Development Guide)

### 2.1 Локальная инициализация и запуск Next.js

1. **Установка системных зависимостей Node.js:**
   Для удовлетворения зависимостей workspace и проверки типов компилятором TypeScript необходимо выполнить команду установки пакетов в корневом каталоге:
   ```bash
   npm install
   ```

2. **Запуск сервера разработки:**
   Для запуска локального сервера Next.js на порту `3000` выполните:
   ```bash
   npm run dev
   ```
   После этого страница симулятора EQUHUB станет доступна по адресу `http://localhost:3000`.

3. **Сборка проекта для продакшена:**
   Для компиляции оптимизированной статической версии веб-приложения:
   ```bash
   npm run build
   ```

4. **Проверка статической типизации:**
   Перед отправкой коммитов обязательно убедитесь в отсутствии ошибок типизации:
   ```bash
   npx tsc --noEmit
   ```

## 3. Кодекс кодирования и правила верстки (Coding Conventions)

* **Строгая типизация TypeScript:** Использование `any` запрещено. Все сущности должны импортировать интерфейсы из `lib/types.ts`.
* **Безопасность SSR (Server-Side Rendering):**
  Поскольку Next.js выполняет предварительный рендеринг компонентов на стороне сервера, использование браузерных API (таких как `window`, `document`, `navigator`, `AudioContext` или `localStorage`) должно сопровождаться проверкой:
  ```typescript
  if (typeof window !== "undefined") {
    // Безопасный запуск в браузере
  }
  ```
* **Использование CSS переменных:** Все цвета элементов интерфейса должны наследоваться от глобальных CSS-переменных, определенных в `app/globals.css` (например, `var(--bg)`, `var(--surface)`, `var(--accent-cyan)`), для поддержки динамического переключения тем оформления.

## 4. Панель администрирования и модерация (Admin Guide)

Раздел 2.10 SRS регламентирует наличие бизнес-инструментов администрирования, включая модерацию объявлений и обработку жалоб.

### 4.1 Автомодерация искусственным интеллектом (AI Moderation)
Для минимизации ручного труда модераторов в `lib/ai.ts` реализован автоматический анализатор контента:
* **Запрещенные ключевые слова:** Алгоритм сканирует заголовки и тексты объявлений на маркетплейсе и в разделе "Работа" на предмет потенциально опасного и мошеннического содержимого. Наличие слов, ассоциирующихся с пирамидами, скамом или обманом (например, `скам`, `обман`, `пирамиды`, `crypto`), автоматически отклоняет публикацию со статусом `approved: false` и блокирует ее отображение.
* **Автоопределение категорий:** AI-модуль осуществляет семантический разбор заголовка и автоматически рекомендует оптимальную категорию маркетплейса (Авто, Недвижимость, Техника, Услуги, Хобби), что повышает точность поиска Elasticsearch.

### 4.2 Мониторинг логов событий (Event Logs)
Административная панель EQUHUB содержит встроенный **терминал мониторинга шины событий в реальном времени**. Он отображает лог транзита запросов от клиентов к СУБД через API Gateway и микросервисы.
* **Зеленый цвет (Success):** Успешные транзакции (оплата Escrow, списание средств, регистрация откликов на вакансии).
* **Желтый цвет (Warning):** Предупреждения безопасности (лимиты запросов Rate Limiter, отключение микрофонов WebRTC).
* **Красный цвет (Error):** Критические ошибки системы и блокировка автомодерации (диспуты Escrow, попытка публикации спам-текста).
