# План тестирования и информационной безопасности EQUHUB

Настоящий документ содержит спецификацию стратегии обеспечения качества и защиты информации для Единой цифровой платформы EQUHUB, соответствующий разделу 13 и 15 Спецификации Требований (SRS).

---

## 1. Стратегия тестирования

Обеспечение качества осуществляется на трех уровнях пирамиды тестирования:

### 1.1 Модульное тестирование (Unit Testing)
* **Инструменты:** Jest (для TypeScript/Next.js/NestJS), Pytest (для Python/FastAPI), Go Testing (для Chat Service).
* **Покрытие:** Минимум 80% кодовой базы, включая критические бизнес-модели: расчет баланса кошелька, логику умного подбора категорий ассистентом AI, валидацию вакансий/резюме.
* **Пример теста:** См. тесты `tests/test_dating_chatbot.py`.

### 1.2 Интеграционное тестирование (Integration Testing)
* **Цель:** Проверка сквозного прохождения сообщений через WebSocket шлюзы, хостинг статических файлов в MinIO S3 и транзакционный кэш Redis.
* **Инструменты:** Supertest, Docker Compose Test Containers.

### 1.3 Сквозное тестирование (E2E Testing)
* **Цель:** Имитация действий реального пользователя на интерфейсе (авторизация, создание объявления, перевод средств в Escrow, отклик на вакансию).
* **Инструменты:** Playwright (для Python и JS).
* **Пример теста:** См. `tests/verify_sound_gen.py`.

## 2. План обеспечения информационной безопасности

Защита данных пользователей является наивысшим приоритетом EQUHUB.

### 2.1 Аутентификация и сессии (JWT HS256)
* Все приватные эндпоинты защищены проверкой подписи токенов JWT HS256.
* Срок жизни Access Token ограничен 15 минутами, Refresh Token — 7 днями.
* Использование заголовка `HTTPOnly Secure` кук для предотвращения XSS-атак при хранении токенов в вебе.

### 2.2 Двухфакторная аутентификация (2FA)
* Реализована по протоколу TOTP (RFC 6238) с использованием приложений Google Authenticator или Яндекс Ключ.

### 2.3 Безопасность API и Rate Limiting
* Лимит запросов: максимум 100 запросов в секунду с одного IP-адреса на уровне API Gateway.
* Защита от Brute-Force атак на эндпоинты регистрации и авторизации.

### 2.4 Защита персональных данных
* Хэширование паролей в БД с использованием соли и алгоритма `Argon2` или `bcrypt`.
* Шифрование данных в покое (Encryption at Rest) для СУБД PostgreSQL.
